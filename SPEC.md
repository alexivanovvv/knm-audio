# knm-audio — Spec

Единый спек проекта: видение, инварианты, тикеты. `BACKLOG.md` — упразднён,
всё перенесено сюда (2026-09-24). Порядок работы: сначала тикет формулируется
здесь (статус «открыт»), потом реализуется, потом статус меняется на «сделан»
с датой — так задачи не теряются и остаются сформулированными.

## 1. Видение

Личный audiobook-PWA для подготовки к экзамену KNM ("Welkom in Nederland"):
7 глав, 36 задач, английская озвучка с отдельно проговариваемыми
нидерландскими терминами. Один файл `index.html` (+ `sw.js` +
`manifest.webmanifest`), без сборки, устанавливается на телефон как обычное
приложение, работает офлайн после первого прослушивания каждого трека.
Разработка и использование — только Алексеем, деплой на
`knm-audio.netlify.app`.

## 2. Инварианты

- **Single-file static PWA, без сборки.** Все правки — прямо в `index.html`
  (инлайн `<style>`/`<script>`). Не превращать в build-проект (Vite/webpack и
  т.п.) без явного запроса.
- **Netlify-хостинг, репозиторий на GitHub** (`alexivanovvv/knm-audio`).
- **Деплой — по накоплению фич, коммит — после каждой правки.** `git commit`
  + `push` после каждого значимого изменения (бесплатно). `netlify deploy
  --prod` — только по явному запросу Алексея в моменте (кредиты Netlify
  ограничены, см. T-04). Локальный dev-сервер `python3 dev-server.py`
  (порт 8765) + пункт "Deploy to Netlify" в меню настроек дают Алексею
  запустить деплой самому, когда он готов.
- **Localhost-only контролы обязаны быть скрыты на проде.** Гейт
  `location.hostname === 'localhost' || location.hostname === '127.0.0.1'`
  — единственный источник правды, никаких доп. флагов. Проверять на каждом
  новом localhost-only контроле (см. T-16).
- **Язык интерфейса (chrome) ≠ язык контента книги.** `STRINGS`/`t()` —
  только для UI-текста (меню, кнопки, футер). `TASK_LABELS` и
  `BOOK[].chTitle`/`chTitleEn` — двуязычный контент книги, задуман таким с
  самого начала, НЕ трогать при работе с интерфейсным i18n.
- **Прогресс — в localStorage**, пока не реализованы аккаунты (T-10). После
  T-10 — PIN-аккаунт должен быть **опциональным поверх** localStorage
  (localStorage остаётся фолбэком/кэшем), не заменой на первом шаге.

## 3. Границы скоупа (пока не делаем)

- Многопользовательские фичи за пределами простого PIN + синка прогресса
  (шеринг библиотек, соцфункции, комментарии).
  Платные/подписочные механики.
- Полноценный OAuth/email-провайдер — сначала PIN (см. решение по T-10 ниже).
- Нативные iOS/Android-сборки — остаётся PWA.

#### T-09 · Fix: объявление главы ломало автовоспроизведение · сделан (24.09, commit e3f1524)
Баг: `loadTrack` ждал chime+речь (несколько секунд) перед `audio.play()` —
в части браузеров (особенно iOS Safari) разрешение на автовоспроизведение к
этому моменту истекало, трек не начинал играть после объявления. Плюс если
`speechSynthesis` не вызывал `onend`/`onerror` (заблокированная/свёрнутая
вкладка) — `loadTrack` подвисал навсегда. Фикс: "разблокировка" audio-
элемента (play+pause в mute) синхронно перед ожиданием озвучки, + timeout-
фолбэк в `speakText`, чтобы промис всегда резолвился.
**Нужна повторная проверка Алексеем** — если проблема была не в этом,
написать конкретный симптом (что именно происходило) для более точного фикса.

#### T-16 · Полоска "локальная версия ≠ прод" с кнопкой деплоя · сделан (24.09, commit ebc988a)

**заработает только после следующего реального деплоя**, до этого момента
баннер будет молчать на localhost, как и раньше.

### Сейчас (в работе, по порядку)

#### T-10 · Аккаунты с логином (PIN, без email) — синк прогресса · сделан (24.09, commit 6a2378e)
`netlify/functions/progress.js` (Netlify Function v2, путь `/api/progress`) +
Netlify Blobs как key-value хранилище; ключ — SHA-256("knm-audio:"+PIN),
считается на клиенте, сырой PIN на сервер не уходит. `GET ?key=` отдаёт
`{updatedAt, data}` или 404, `POST {key, payload}` перезаписывает.
`package.json` добавлен только ради зависимости `@netlify/blobs` для функции
(у сайта по-прежнему нет build-шага).
Фронтенд: пункт меню "Sync via PIN" — по клику `window.prompt` для ввода/
создания PIN (4-8 цифр, как в `deployConfirm` уже используется `window.confirm`,
стиль решения выдержан). Если для PIN уже есть данные на сервере — подтягиваются
и перезаписывают локальные (localStorage-ключи: прогресс, listened, тема,
автоплей, анонс, пауза между главами, режим субтитров, язык); если нет —
текущее локальное состояние отправляется как стартовое. После входа при
каждом изменении (толчок в `saveListened`/`saveProgress`/тоглы настроек)
данные пушатся с debounce 700мс; при старте приложения, если PIN уже
сохранён, лишний раз подтягивается сервер и мержится, если там `updatedAt`
новее локального (`localStorage.welkomPinLastSync`) — так более свежие
изменения с другого устройства подхватываются и при обычном открытии
страницы, не только в момент ввода PIN.
**Локальное тестирование:** `dev-server.py` эмулирует `/api/progress` через
JSON-файлы в `.local-blobs/` (не коммитится) — PIN-синк можно проверить на
localhost без реального деплоя; на проде эмуляция не используется, там
работает настоящая Netlify Function.
**Известное упрощение (сознательно, не баг):** конфликтов между двумя
устройствами, изменившими данные независимо и одновременно, нет — просто
last-write-wins по `updatedAt`. Для личного использования на 1-2 устройствах
этого достаточно.
**Acceptance:** ввёл PIN на телефоне → прогресс появился на ноуте после
ввода того же PIN; без PIN всё работает как раньше (чисто локально). ✅
проверено локально через эмуляцию `dev-server.py`.

#### T-12 · Выбор цветовой схемы — 6 тем (3 тёмных, 3 светлых) · сделан (24.09, commit 04422ae)
Кнопка темы в меню теперь циклит по 6 темам: dark-amber (бывший дефолт),
dark-teal, dark-violet, light-paper (бывший дефолт), light-sky, light-mint —
каждая со своей палитрой bg/ink/accent через `:root[data-theme="..."]`.
Старые значения `localStorage[THEME_KEY]` ('dark'/'light') мигрируют
прозрачно на dark-amber/light-paper. `theme-color` meta-тег обновляется
вместе с темой. Меню не закрывается после клика — можно прощёлкать все 6
и увидеть live-превью.

#### T-13 · Режим субтитров micro / full · сделан (24.09, commit b4eb1fb)
Новый пункт меню "Subtitles mode" циклит Full (прежний полноэкранный
drawer, без изменений) / Micro (одна строка субтитров прямо над плеером,
внутри `.player-inner`, список глав не перекрывает). CC-кнопка открывает
активный режим; смена режима при открытых субтитрах переоткрывает их в
новом виде. По умолчанию — full, старое поведение не сломано.

#### T-14 · Редизайн плеера в духе Apple Music / Spotify / Yandex Music · сделан (24.09, commit b4b3f33)
Обложка увеличена (60px, крупнее скругление и тень), заголовок трека крупнее
и жирнее (800), transport-контролы переструктурированы в 3 зоны как в
Spotify web-плеере: CC слева, prev/±15s/play/next по центру (play — самая
крупная кнопка, 3.3rem), скорость справа. Прогресс-бар плавнее (тоньше в
покое, подрастает и увеличивает thumb при hover/active). Вся функциональность
осталась на виду, ничего не свёрнуто в мини-плеер.

#### T-15 · Режим отметки завершённости глав/подзадач (select/deselect) · сделан (24.09, commit fd49385)
Кнопка-карандаш в `.overview` включает режим редактирования: иконка меняется
на галочку, у каждого трека вместо "✓"/пусто — чекбокс-иконка
(`SELECT_ON_ICON`/`SELECT_OFF_ICON`), тап по треку переключает "прослушано"
вручную (можно снять отметку с уже прослушанного). Тап по заголовку главы в
этом режиме массово переключает все треки главы (все → снять, не все → все
включить), а не сворачивает/разворачивает главу. Вне режима редактирования
поведение прежнее (тап по треку — играть, тап по главе — сворачивать).
Использует существующий `listened`-Set/`LISTENED_KEY`.

## 6. Процесс разработки

1. Тикет формулируется в этом файле (статус «открыт») до начала кода.
2. Реализация в `index.html` (+ при необходимости `netlify/functions/`,
   `dev-server.py`).
3. `node --check` на извлечённом `<script>` + сверка `getElementById` ↔
   `id` перед коммитом (нет браузера на localhost в этой песочнице).
4. `git commit` + `push` сразу после — конвенция T-04.
5. Статус тикета → «сделан (дата, commit)».
6. `netlify deploy --prod` — только по явному запросу Алексея.

## 7. Связанные документы
